# ปรับจากหน้าสื่อการสอนเป็นหน้าหลักของเกม

> **ทิศทางล่าสุด: ออกแบบก่อนโค้ด** — เอกสารนี้บันทึกการแก้ต้นแบบที่เกิดขึ้นก่อนคำชี้แจงล่าสุด ไม่ใช่การอนุมัติแบบสุดท้าย อ่าน [แผนออกแบบเกม 7 จุด](GAME_EXPERIENCE_REDESIGN_PLAN.md) รอบนี้แก้เอกสารเท่านั้น งานถัดไปคือรับข้อแก้และทำ wireframe ก่อนคำสั่งเริ่มโค้ดใหม่

9 ตุลาคม 2026 — ผู้ใช้ทดลองและส่งภาพต้นแบบ จากนั้นขอแก้ 7 จุด

## สิ่งที่แก้จริงในรอบนี้

| ข้อ | พฤติกรรมใหม่ | ข้อจำกัด |
| --- | --- | --- |
| 1 โครงการเป็น UI ในเกม | ฉากเต็มพื้นที่ viewport, HUD โครงการลอยด้านขวา พับได้, เงินด้านบน, เครื่องมือด้านล่าง; เปิดสมุด/บท/ร้าน/คลังเป็นหน้าทับโลก | เกณฑ์วัสดุยังแยกจากการประเมินความรู้ |
| 2 สอนเล่นชัดเจน | ผู้ช่วย 6 ขั้น: แนะนำ → เดิน → โต๊ะ → เก็บแผน → ยืนยันซื้อ → ปู; มีปุ่มนำทาง ทำจริงแล้วเปลี่ยนขั้น ซ่อน/เริ่มสอนใหม่ได้ | ไม่มีเซฟสถานะสอนเล่น และไม่ให้รางวัลความรู้จาก tutorial |
| 3 กล้องใกล้และหมุน | กล้องติดตามตัวละครที่ zoom คงที่ 0.95, เอาล้อเมาส์ซูมออก, ปุ่มหมุนทีละ 90° ครบ 4 มุม, กลับกล้องไปตัวละคร | ตัวเลข zoom เป็นสเกลภายใน ไม่มีตัวเลือกซูมสำหรับผู้เล่น; PNG จริงยังไม่โหลด |
| 4 ตั้งค่าในเกม | ปุ่มตั้งค่าเปิดขนาดข้อความและลดการเคลื่อนไหว; ปรับข้อความทั้ง HTML และป้ายโลก; ลดท่าเดินและการหน่วงกล้อง | เก็บเฉพาะรอบเปิดแท็บ เคารพ prefers-reduced-motion ตอนเริ่ม |
| 5 เต็มจอ | ปุ่ม requestFullscreen/exitFullscreen, ฟัง fullscreenchange อัปเดตสถานะ; dialog อยู่ภายในองค์ประกอบเต็มจอ | ถ้าบราวเซอร์ปฏิเสธ แจ้งปัญหา/เสนอ F11 ไม่แสดงว่าทำสำเร็จแล้ว |
| 6 หลบสิ่งก่อสร้าง/ของ | BFS ใช้ฐานจริงทุกวัตถุในผัง 4-neighbour; คลิกอาคาร/ป้ายแล้วเดินไป interaction; หมุนแล้ว inverse projection กลับพิกัดเดิม | ยังไม่มีเฟอร์นิเจอร์ที่ผู้เล่นเพิ่มเอง หรือ NPC เดิน ต้องเพิ่ม blockers ตามระบบนั้นภายหลัง |
| 7 ดีไซน์ใหม่ | HUD สีเขียวเข้ม–ทอง, สมุด/การ์ดสีครีม, แถบเครื่องมือ, ผู้ช่วย, เป้าหมาย/ทางเดินจุด, ภาพอาคารมีความสูงและ depth ตามตำแหน่ง | ภาพทั้งหมดในโลกยังเป็น placeholder geometry ไม่มีภาพ/เสียงชุดสุดท้าย |

หน้าต่างเรียนยังคงการสอนตรง ๆ: เหตุใดต้องคำนวณ ข้อมูล/หน่วย สูตร การตรวจ และการตัดสินใจ ไม่มีการย้ายความรู้ไปซ่อนในบทสนทนาเท่านั้น แผนกลับจากบทตรงขั้นยังคงร่างและโฟกัส

Tutorial บันทึกเหตุการณ์ควบคุมเท่านั้น ไม่ประเมินว่าเหตุผลถูกหรือเกิด mastery หากเล่นนอกลำดับ เหตุการณ์ที่ทำแล้วจะถูกจำในแท็บนี้ เมื่อถึงขั้นนั้นไม่บังคับทำซ้ำ การเริ่ม tutorial ใหม่ไม่รีเซ็ตงบหรือวัสดุ

## กล้องและภาพตามทิศ

พิกัดจริงและฐานชนไม่หมุน เปลี่ยนเฉพาะการฉายภาพ: หมุนพิกัดรอบศูนย์กลาง (16,12) → ฉาย isometric → render. คลิกใช้ camera.getWorldPoint → inverse projection/inverse rotation → หา logical cell ก่อน pathfinding. ขนาดห้องและการคำนวณพื้นที่ไม่ใช้ระยะจากภาพมุมเอียง

ภาพตัวละครเป็น billboard ตั้งตรง ไม่เอา PNG ไปหมุน 90° บนจอ เลือก NE/SE/SW/NW ตามทิศเดินจริงและ view turn. ภาพเฟอร์นิเจอร์เลือก N/E/S/W ที่เห็นจากกล้อง ขณะที่ทิศหันจริงของวัตถุคงเดิม ตัวอย่างวัตถุหัน logical S: view 0/1/2/3 เลือกภาพ S/W/N/E ตามลำดับ

โค้ด `src/domain/view.ts` มี mapping ทิศพร้อมทดสอบ; `WorldScene` ใช้ mapping กับใบหน้า/ด้านหลังของตัวละคร placeholder. ยังไม่มี PNG loader/texture manifest เพราะยังไม่ได้รับชุดภาพจริง อย่าอ้างว่าชุด PNG ถูกผูก runtime แล้ว

## ผลกระทบข้อมูล/การตรวจ

- งบ ราคา สูตร พื้นที่ และเงื่อนไข A/B/C/D ไม่เปลี่ยน ไม่มีการแก้เฉลยจากการเปลี่ยนกล้อง
- ต้องเพิ่ม camera view, text scale, reduced motion, quest collapse และ tutorial state ในสัญญาเซฟเมื่อทำ S5 ขณะนี้ยังไม่มี durable save/migration
- ข้อมูลครูประเมิน/พอร์ต/สิทธิ์ความรู้ยังเป็นงานถัดไป ไม่ใช้การผ่าน tutorial แทนหลักฐาน
- การวางเฟอร์นิเจอร์ S3 ต้องใช้พิกัดจริงตรวจ และทำ preview ภายใต้ทั้ง 4 มุม; ไม่สลับ width/height จริงเพียงเพราะกล้องหมุน
- ครอบ UI ไม่รับคลิกทะลุ ขณะ dialog เปิดให้หยุดเดิน; ปรับขนาดหน้าจอ/เต็มจอไม่รีเซ็ตโครงการ

## การตรวจรอบนี้

TypeScript/build ผ่าน; npm test 14 กรณี รวมฉาย/ย้อนกลับทุกช่องทั้ง 4 มุม, ทิศภาพ, เส้นทางหลบฐานชน และ tutorial ที่เล่นนอกลำดับ

Chromium headless ทดลอง HUD/สอนเล่น/เดินไปโต๊ะ/กล้องติดตาม/หมุน/ตั้งค่า/เต็มจอ รวมเส้นทาง A/B และกลับร่างจากบท; ตรวจข้อความ 150% และ viewport 720px. ยังไม่ได้ทดลองบนเครื่องผู้ใช้หรือใช้ PNG จริง

## ข้อเสนอถัดไป

1. เพิ่มแผนที่ย่อและหมุดนำทาง เพื่อรู้ว่าร้าน/พื้นที่อยู่ทิศไหนเมื่อใช้กล้องใกล้ โดยไม่กลับไปซูมโลกเต็มจอเป็นหลัก
2. เพิ่มกรอบเลือกวัตถุและคำสั่งใกล้ตัวละคร เช่น ใช้งาน/ดูข้อมูล/จัดพื้นที่ ให้โลกเป็นจุดเริ่มกิจกรรมมากขึ้น
3. ทำ S3 เฟอร์นิเจอร์และ NPC บทสนทนาสั้นที่ตอบผลโครงการจริง โดยเก็บคำสอนและข้อมูลโจทย์ให้เปิดอ่านซ้ำได้

ข้อเสนอเหล่านี้ยังไม่ implement ในรอบนี้ งานจัดเฟอร์นิเจอร์ → ประเมิน/พอร์ต → เซฟเป็น backlog หลังได้รับคำสั่งเริ่มโค้ดใหม่; งานปัจจุบันคือแผนและแบบหน้าจอ

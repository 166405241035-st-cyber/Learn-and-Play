# ตัวเลือกเพิ่มเติมนอกเหนือจาก 7 จุด และแผนตรวจภาพคอมมิช

9 ตุลาคม 2026 · **รายการให้ผู้ใช้เลือก ไม่ใช่รายการที่อนุมัติให้เขียนทั้งหมด**

ต่อจาก [แผน 7 จุด](GAME_EXPERIENCE_REDESIGN_PLAN.md) รอบนี้อัปเดตเฉพาะเอกสาร เก็บ 7 จุดเดิมเป็นฐาน ไม่ขยายขอบเขตโค้ดอัตโนมัติ บางตัวเลือกมีแนวคิดอยู่ในเอกสารเดิมแล้ว; ตารางนี้แยกให้เลือกความสำคัญใหม่ ไม่อ้างว่าคิดใหม่ทั้งหมด

## 1. หลักจากเกมตัวอย่าง

- [Factorio FFF #361](https://www.factorio.com/blog/post/fff-361): จัด tips เป็นหัวข้อ ค้นหาและเปิดกลับได้ มีสาธิตกลไก และใช้ข้อความเตือนที่แยกสาเหตุ ข้อเสนอของเรา: สมุดช่วยค้นตามปัญหา ป้ายข้อมูลของ และตัวอย่างทดลองที่ไม่ยุ่งกับเงินจริง
- [OpenRCT2 main interface](https://docs.openrct2.io/en/latest/playing/main_interface/): แยกกลุ่มเครื่องมือ มีหน้าต่างแผนที่ มุมมองซ่อนองค์ประกอบ และ screenshot ในเมนู ข้อเสนอของเรา: แผนที่ย่อและโหมดถ่ายผลงานที่เข้าใจง่าย ไม่ใช้เครื่องมือทั้งหมดของเกมนั้น
- [Stardew Valley Options](https://wiki.stardewvalley.net/Options): มีตัวเลือกแถบเครื่องมือ เสียงหลายกลุ่ม และการอ่าน UI แยกมุมโลก ข้อเสนอของเรา: เสียงตอบรับปรับได้และเครื่องมือที่ไม่บังตัวละคร

ตรวจเว็บวันที่ 9 ตุลาคม 2026 สิ่งที่ตามมาเป็นการออกแบบของ Learn-and-Play ไม่อ้างว่าเกมตัวอย่างมีทุกฟีเจอร์นี้ ไม่ใช้ความนิยมของเกมเป็นหลักฐานประสิทธิผลการเรียน

## 2. ตัวเลือกสำหรับตัดสินใจ

งานเพิ่มระบุเป็นเล็ก/กลาง/มากเมื่อเทียบกันในโครงการ ไม่ใช่เวลารับประกันหรือยอดราคา

| ID | ข้อเสนอและตัวอย่างการเล่น | ประโยชน์ | งานเพิ่ม/ข้อระวัง | คำแนะนำ |
| --- | --- | --- | --- | --- |
| E1 | **เงาตัวอย่างก่อนวาง**: ของตามเมาส์ แสดงฐานและหน้าที่ต้องมีทางเข้า พร้อมเหตุผลถ้าวางไม่ได้ | ลองจัดพื้นที่ได้โดยไม่เสียของ ไม่ต้องเดาว่าภาพกินกี่ช่อง | กลาง; ใช้ฐานเดียวกับเดินและตรวจทาง เสียง/สีไม่เป็นสัญญาณเดียว | เลือกก่อน; เป็นการทำ S3 เดิมให้เห็นภาพ |
| E2 | **เปรียบเทียบทางเลือก A/B ในแผนเดียว**: วางยอดจ่าย ของเหลือ เงินคงเหลือ และเหตุผลข้างกัน | การคำนวณเป็นการตัดสินใจที่มีผลในเกม | กลาง; แยกค่าผู้เล่นกรอกจากค่าที่ตรวจ ไม่ทำเครื่องคิดเลขเฉลยทุกช่อง; ประเมินยังเป็นงานใหม่ | เลือกก่อน; ทำรูปแบบให้ชัดกว่าแผนเดิม |
| E3 | **คำขอจาก NPC แบบเลือกได้**: เพื่อนบ้านขอพื้นที่อ่านหนังสือที่เดินเข้าได้ ผู้เล่นเลือกสไตล์เอง | มีเหตุผลให้ทำโครงการและเห็นผู้ใช้พื้นที่ | มาก; บทสนทนา เงื่อนไขและผลโลก ต้องไม่บังคับคำตอบเดียวหรือผูกความรู้กับความพอใจ NPC | เลือกหลังวงจรแรกพร้อม |
| E4 | **แผนที่ย่อพับได้**: ตัวเรา โต๊ะ ร้าน ศูนย์เรียน และเป้าหมายปัจจุบัน | ช่วยนำทางเมื่อกล้องใกล้ตัว | กลาง; จุดแผนที่กับกล้องหมุนต้องตรงกัน เริ่มจากแผนที่อ่านตำแหน่ง ไม่ teleport | เลือกเมื่อทดลองแล้วพบว่าหลง |
| E5 | **สมุดช่วยค้นตามปัญหา**: “กล่องไม่พอ”, “ทำไมปัดขึ้น”, “คืนได้ไหม” แล้วเปิดบทตรงจุด | กลับมาขอช่วยเองโดยไม่เล่น tutorial ทั้งชุด | เล็ก–กลาง; ผูกกับ lesson IDs เดิม กลับร่างได้; บันทึกความช่วยใน assessment | เลือกก่อนเมื่อบทเริ่มหลายหน้า |
| E6 | **ตรึงแผนสองฉบับเพื่อดูผลต่าง**: แผนแรกเทียบแผนแก้ ชี้จำนวน/ราคา/เหตุผลที่เปลี่ยน | เห็นว่าการแก้ความคิดทำให้โลกดีขึ้นอย่างไร | กลาง; เก็บฉบับ immutable ไม่ย้อนยอดเงินจริง; ต่อพอร์ตเดิม | เลือกก่อนพอร์ต ไม่ต้องเพิ่มระบบ replay ทั้งเกม |
| E7 | **โหมดทดลองแผนไม่ใช้เงินจริง**: ปรับจำนวนแล้วเห็นผลประมาณก่อนยืนยันซื้อ | ลดความกลัวซื้อผิด เหมาะกับการเปรียบเทียบ | กลาง; แสดง “จำลอง” ชัด ไม่มีของหรือรางวัลเข้าคลังจากหน้าลอง | เลือกได้; เริ่มจากตะกร้าคำนวณก่อนซื้อ แทนโลกจำลองอีกใบ |
| E8 | **โหมดถ่ายผลงาน**: ซ่อน HUD ชั่วคราว เลือกมุม ใส่คำอธิบาย แล้วกลับเล่น | พอร์ตดูเป็นผลงานในเกมและอธิบายการเลือกได้ | กลาง–มาก; ภาพตกแต่งไม่ยืนยันความรู้ ต้องผูก evidence/attempt และแจ้งถ้าจับภาพล้มเหลว | ทำพร้อมพอร์ต |
| E9 | **เสียงตอบรับที่มีความหมาย**: ซื้อ/คืน/วางผ่าน/วางติดต่างกัน ปรับเสียงแต่ละกลุ่มได้ | โลกตอบสนองและรู้ผลการกระทำทันที | กลาง; source/use terms, เริ่มหลัง gesture, มีข้อความแทนเสียง | ทำหลัง UI และธุรกรรมถูกต้อง; มีสเปกเดิมแล้ว |
| E10 | **ของตกแต่งและเรื่องราวจากการเล่น**: เปลี่ยนป้าย สี หรือมุมแสดงผลงานจากการทำโครงการ | เห็นพื้นที่เติบโตและเป็นของผู้เล่น | กลาง–มาก; แยกรางวัลเล่นจากสิทธิ์ความรู้ ไม่ใช้ streak/เวลาบังคับกลับเล่น | เลือกหลังพอร์ต/เซฟ มีแนวคิดรางวัลเดิมแล้ว |

**ชุดแนะนำเพื่อเริ่มเล็ก:** E1 + E2 + E5 และเตรียมข้อมูล E6 สำหรับพอร์ต ทั้งหมดต้องเข้ากับ 7 จุดเดิม ไม่เริ่มโค้ดจนได้รับคำสั่ง ส่วน E4 ใช้ผลทดลองตัดสิน ไม่เพิ่มเพราะทุกเกมต้องมีแผนที่ย่อ

## 3. ตัวเลือกที่เสนอให้เลื่อนไปก่อน

- กลางวัน/กลางคืนหรือสภาพอากาศ: เพิ่มบรรยากาศได้ แต่กระทบแสง PNG ความอ่านง่ายและการทดสอบ ยังไม่ช่วยวงจรแรกมากพอ
- ผู้เล่นออนไลน์หลายคน: เพิ่มบัญชี เซิร์ฟเวอร์ ความขัดแย้งของเงิน/ของ/หลักฐานและขอบเขตข้อมูล
- NPC เดินจำนวนมาก: เพิ่ม dynamic pathfinding และการบังฉากก่อนรู้ว่าจำเป็นหรือไม่
- AI สนทนาอิสระ: เนื้อหา/การตรวจความถูกต้อง/ค่าใช้จ่ายยังไม่กำหนด บทสอนคณิตต้องมีหลักและคำตอบตรวจได้
- ภารกิจรายวัน/นับเวลาบังคับ/อันดับคะแนนรวม: เสี่ยงให้เล่นเร็วแทนคิด ไม่ใช้แทนประเมินทักษะ

รายการเหล่านี้ยังไม่ถูกเพิ่มเป็น requirement ผู้ใช้สามารถเลือกมาวางแผนเฉพาะได้ภายหลัง

## 4. ภาพคอมมิช: สถานะและสิ่งที่ต้องได้รับ

พบอัปโหลดใหม่ 33 PNG บน GitHub ระหว่างรอบนี้และตรวจไฟล์แล้ว ดู [ผลตรวจรายกลุ่ม/รายไฟล์และแผนแก้โค้ดใน doc](../art-audio/COMMISSIONED_ART_REVIEW.md) มี alpha ครบแต่ยังมีมุม/เฟรม/registration ต้องแก้ ไม่อนุมัติหรือรวม runtime อัตโนมัติ ข้อตกลงการใช้ภาพและทิศที่ไม่ชัดยังต้องยืนยัน

### 4.1 รายการตรวจเทียบแบบ

| ตรวจอะไร | ฐานที่ใช้เทียบ | ผลที่ต้องบันทึก |
| --- | --- | --- |
| ชิ้นงานตรง ID | PROTOTYPE_PRODUCTION และชื่อไฟล์ใน PROTOTYPE_PROMPTS | ระบุชิ้น/เฟรม/มุม; ไม่เดา ID เมื่อไม่ชัด |
| สไตล์ร่วม | reference ตัวอย่างและ palette ที่อนุมัติ | ขนาดสัมพัทธ์ เส้น สี แสงเหมือนกัน ไม่ตัดสินจากความสวยชิ้นเดียว |
| มุมและฐาน | isometric 2:1, tile 128×64, footprint/front ตาม SCENE_OBJECT_SPEC | ฐานตรงตาราง ไม่ลดพื้นที่โจทย์เพื่อให้ภาพพอดี |
| canvas/anchor | เช่น player 160×192 จุดเท้า (80,176); grass 128×64 (64,32); desk 256×256 (128,224) | ขนาดจริง จุดยึดและขอบโปร่งใส ไม่อ้างผิดเพราะ canvas ใหญ่กว่าโดยไม่ดูเหตุผล |
| เดินคู่ 01/02 | ทิศเดียวกัน สัดส่วนและจุดเท้าร่วม | การเปลี่ยนเฟรมไม่ทำฐานเลื่อนหรือหัวตัวละครโตสลับ |
| กล้อง 4 มุม | CAMERA_VIEW_PROMPTS ฉบับ 0.2 | ประตูเดิมยังอยู่ผนังจริงเดิม ไม่หมุน PNG แบน/กลับด้านแทนมุมที่ขาด |
| อาคาร body/roof | layer แยก canvas/anchor ตรงกัน | จางหลังคาได้ ไม่มี body ซ้ำใน roof |
| alpha/เงา/ข้อความ | RGBA โปร่งใส เงาสัมผัสทำแยก ชื่อราคา/สูตรเป็น code | ไม่มีพื้นขาว/ลายตารางติดภาพ ไม่มีตัวเลขสูตรฝังใน sprite |
| ใช้ได้ในเกม | ตรวจที่สเกลกล้องจริงและทุกมุมที่มี | แยก “ไฟล์ผ่าน” จาก “integrated”; ยังไม่อ้างผ่าน runtime ถ้าไม่ได้ทดสอบ |
| ที่มา/การใช้ | ข้อตกลงคอมมิชและไฟล์ต้นฉบับ | บันทึกสิทธิ์ใช้งานที่ได้รับจริง ไม่เดาข้ออนุญาต |

### 4.2 ถ้าไม่ตรง จะเลือกแก้ส่วนใด

1. **แก้ภาพ:** มุมผิด ขาดทิศ จุดเท้าเลื่อน ตัวละครเปลี่ยนรูปร่าง พื้นหลังติด หรือ roof รวมกับ body ส่งคำขอแก้เฉพาะจุดพร้อม reference
2. **แก้สเปก/manifest ในเอกสาร:** ภาพดีและฐานตรง แต่ต้องใช้ canvas/anchor ต่างจากค่าทดลอง บันทึกค่าจริงและชื่อไฟล์ใหม่โดยรักษา footprint/หน่วยคณิต
3. **แก้แผนโค้ดใน doc:** ระบุ loader, texture/frame mapping, sprite origin/scale, projected anchor, depth และ roof fade ที่ต้องปรับตามภาพ แต่ยังไม่แก้ `src` อัตโนมัติในรอบออกแบบ
4. **ปรับเป้าหมายใหญ่:** ถ้าจะเปลี่ยน projection/ขนาดฐาน/จำนวนมุม ต้องไล่ผัง คลิก เดิน การวาง กล้อง พร็อมป์ และโจทย์ที่เกี่ยวก่อนรับแบบใหม่ ไม่แก้คณิตตามภาพโดยเงียบ ๆ

หากมีภาพจากพร็อมป์เก่ามุมเดียว ยังใช้เป็น style sample/มุมฐานได้ ไม่จำเป็นทิ้งทั้งชุด แต่ยังไม่ถือว่ารองรับหมุนครบสี่มุม รายงานต้องระบุรายการมุมที่ขาดและชิ้นที่ใช้ต่อได้ก่อนเสนอผลิตเพิ่ม

### 4.3 แบบบันทึกผลเมื่อได้รับภาพ

| Asset ID/ไฟล์ | สิ่งที่ตรง | จุดต้องแก้พร้อมเหตุผล | ค่าจริง canvas/anchor | แก้ภาพ/แก้ doc/แผนโค้ด | สถานะ |
| --- | --- | --- | --- | --- | --- |
| ชุด 33 PNG | ตรวจ alpha/canvas และภาพรายชิ้น | ดู COMMISSIONED_ART_REVIEW | มีตารางค่าจริงในรายงาน | แผนแก้รายกลุ่มในรายงาน | incoming / needs further review |

ผล review แก้ ASSET_REGISTRY, PROTOTYPE_PRODUCTION, พร็อมป์ที่เกี่ยว และ PROJECT_HANDOFF ให้ตรงกัน ส่วน runtime ต้องได้รับคำสั่งเริ่มหรือรวมภาพก่อน ไม่เพิ่มป้าย integrated เพียงเพราะชื่อไฟล์ถูก

## 5. วิธีเลือกและงานต่อไป

ตอบเป็น ID ได้ เช่น “E1 E2 E6 ก่อน, E3 ไว้ทีหลัง” หรือแก้เงื่อนไขเป็นข้อ ๆ เมื่อเลือกแล้วผู้ช่วยจะเพิ่มลำดับงาน ผลกระทบและเกณฑ์ตรวจในแผนหลัก โดยไม่ถือว่าการเลือกฟีเจอร์เท่ากับสั่งแก้โค้ดทันที เลือกข้อเสนอแก้ภาพในรายงานก่อนผลิตชุดเพิ่ม

## 1. หลักร่วมของหน้าจอ

Desktopก่อน ขนาดอ้างอิง1600×900 ไม่ล็อกขนาดหน้าต่าง panelกว้างไม่เกิน1280px สูงไม่เกิน90vh ย่อจอแล้วส่วนแปลน/ข้อความเรียงบนล่าง เลื่อนเนื้อหาแทนย่อฟอนต์; viewportเล็กกว่า1024pxเป็นlayoutซ้อน ไม่อ้างรองรับมือถือเต็มรูปแบบแล้ว
ฟอนต์ไทย bodyตั้งต้น20px ปรับ100/125/150%; สูตร22pxขึ้นไป ปุ่มสูงอย่างน้อย44px ตัวเลข/หน่วยมีlabelเต็มไม่พึ่งplaceholder ใช้ชื่อหน่วยอ่านได้ เช่นตารางเมตรคู่m²
headerคงชื่อโครงการ สถานะ และปิด; footerคงปุ่มหลักและสถานะบันทึก ส่วนเนื้อหาเลื่อนเอง focusอยู่overlay เปิดแล้วคลิกไม่ทะลุโลก Escapeปิดหรือยกเลิกวางตามบริบท หากdialogยืนยันเปิดอยู่ Escapeยกเลิกdialogก่อน
ทุกสถานะมีข้อความคู่สัญลักษณ์ ไม่ใช้สี/เสียงอย่างเดียว world timeหยุดเมื่ออ่าน ขยายข้อความ/ลดmotionไม่เป็นhelpคณิตศาสตร์

สถานะบันทึกเสนอ: “มีการแก้ไข”→“กำลังบันทึก…”→“บันทึกในเครื่องแล้ว เวลา…”; ถ้าล้มเหลว “ยังบันทึกไม่สำเร็จ” พร้อมลองใหม่/ส่งออกกู้คืน ต้องแสดงตามผลจริง ห้ามขึ้นsuccessก่อนtransactionจบ ชื่อdraftในความจำไม่แปลว่าบันทึกหลังปิดbrowserได้

## 2. PLAN — หน้าวางแผน

layoutสองส่วน: ซ้ายประมาณ45%เป็นแปลน/ข้อมูล ขวา55%เป็นขั้นเหตุผล footerไม่บังช่องกรอก ผู้เล่นเปิดขั้นใดก็ได้ ไม่บังคับwizardเส้นตรง

| ส่วน | สิ่งที่แสดง/กรอก | ปุ่มและพฤติกรรม |
| --- | --- | --- |
| Header | ชื่อ เป้าหมาย ฉบับแผน งบเริ่มต้นและยอดโครงการจริง | เปลี่ยนเป้าหมาย/ดูเงื่อนไข/ปิด |
| แปลนซ้าย | 4×6ช่อง labelด้านเป็นm ตารางช่อง1m²; แยกactual/required | ซูมแปลน/สลับตาราง/บทพื้นที่; ไม่วัดจากภาพโลกเฉียง |
| ข้อมูลสินค้า | A1.5m²/box180; B2m²/box250; allowance10%จากพื้นที่ | ดูร้าน/คำอธิบายหน่วย; ข้อมูลโจทย์ไม่ถือhint |

| Footer | สถานะร่างและsave | “บันทึกแผน” “ใช้จำนวนนี้ที่ร้าน” “กลับโลก” |

“ใช้จำนวนนี้ที่ร้าน”ใส่material/boxesลงตะกร้าอ้างplanRevisionId ไม่หักเงินจนยืนยันซื้อ ผลตรวจแผนไม่ล็อกการซื้อในฝึกถ้าผู้เล่นตั้งใจลองจำนวนที่ยังไม่พอ แต่ร้านต้องปฏิเสธยอดเกินเงิน/จำนวนไม่เป็นเต็มบวก
หากร่างไม่ครบกดใช้ร้าน ให้บอกช่องจำนวนวัสดุที่ต้องมี; ไม่บังคับเหตุผลผ่านก่อนซื้อ หลังซื้อแผนยังแก้ได้ แต่ label“แผนแก้ยังไม่ได้ใช้ซื้อ”จนมีธุรกรรมอ้างฉบับนั้น
งบแผนเปรียบเทียบเป็นงบเริ่มต้น4,000 ส่วนซื้อเพิ่มใช้ยอดจริงคงเหลือ แสดงสองค่าแยก ไม่หักค่าใช้จ่ายแผนทั้งหมดซ้ำจากเงินหลังซื้อ

## 3. LESSON — เปิดบทตรงจุด

เปิดแทนบริเวณขวาของPLANหรือเป็นpanelจากศูนย์เรียน มี“กลับแผนขั้น…”พร้อมจำตำแหน่งเลื่อนและช่องที่focus ไม่มีoverlayหลายชั้นกดปิดแล้วร่างหาย

| ช่วง | ข้อความตัวอย่างบทกล่อง | การลอง |
| --- | --- | --- |
| ทำไมต้องรู้ | “ร้านขายเป็นกล่องเต็ม เราต้องซื้อให้พอปูและสำรอง” | แยกหน่วยซื้อกับหน่วยพื้นที่ |
| ข้อมูล | “ต้องเตรียม26.4m²; Aกล่องละ1.5m²” | เปิดเงื่อนไขเดิม |
| หลักการ | “หารเพื่อหาจำนวนกล่อง แล้วเลือกจำนวนเต็มน้อยที่สุดที่ยังพอ” | ปุ่มแสดงตัวอย่างเป็นworked-exampleเมื่ออยู่assessment |
| คำนวณ/ตรวจ | ตัวอย่าง17.6;17ได้25.5;18ได้27 | โจทย์ฝึก10/3และ12/3; เก็บคำตอบก่อนเฉลย |

## 4. ASSESSMENT INTRO — ก่อนเริ่ม

แสดงชื่อและสิ่งที่วัด เช่นSPACE-INDEPENDENT-01 “ใช้ข้อมูลใหม่ในบริบทเดิม”; 3×5m เผื่อ10% งบ2,100 C/D; ไม่จับเวลา; calculatorได้; helpบันทึก; เหตุผลยังรอตรวจหากไม่มีผู้ตรวจ
ปุ่ม“เริ่มงาน”สร้างattempt+snapshot ไม่สร้างใหม่ทุกครั้งที่เปิดหน้า ปุ่ม“กลับไปฝึก”ไม่เสียสิทธิ์ ถ้ามีdraftเดิมแสดง“ทำต่อ”และ“เริ่มงานใหม่”โดยอธิบายเก็บงานเก่า
checkpointdecimalมีเครื่องมือเฉพาะแจ้งก่อนเริ่ม ไม่เอากฎไม่ใช้calculatorไปบังคับC/D

## 5. ASSESSMENT WORK — ระหว่างทำ

ซ้าย35%ข้อมูลโจทย์คงที่และแปลน3×5; ขวา65%คำตอบห้ากลุ่มตามFIRST_UNIT_ASSESSMENT:ข้อมูล→หลักการ→คำนวณ→ตรวจ→ตัดสินใจ Tab/keyboardไปครบ ปุ่มhelpอยู่ทุกกลุ่ม
ส่วนC/Dเป็นตารางแถวต่อmaterial กรอกboxes/coverage/cost/reserve/remaining ทั้งคู่ ไม่ซ่อนตัวเลือกDหลังเลือกC ช่องหน่วยมีตัวเลือกและอธิบาย ไม่ให้หน่วยที่ผิดถูกnormalizeจนดูผ่าน
ไม่มีlive correct/incorrectหรือauto-computeเฉลยในโหมดอิสระ หากเรียก“ช่วยตรวจขั้นนี้”ถือsetup/feedback-assistanceและเก็บระดับที่นิยามไว้ ไม่มีทางใช้practice checkerกับassessmentเดียวกันโดยไม่บันทึกช่วย
ช่วยเปิดโจทย์ฝึก/บทสอนจากงานนี้เก็บexposureในattempt; กลับโลกไปอ่านบทที่เกี่ยวข้องขณะattemptยังactiveต้องเก็บexposureด้วย หรือพักงานโดยยังรักษาhelp history ห้ามถือคำตอบแรกอิสระหากเฉลยเดียวกันถูกดูแล้ว
“ตรวจความครบก่อนส่ง”ตรวจเฉพาะช่องว่าง รูปแบบ/หน่วยที่อ่านไม่ได้ ไม่เฉลยค่าถูกผิด; “ส่งงาน”แสดงรายการช่วย/เครื่องมือและถามยืนยัน เก็บsubmittedWorkimmutable ข้อมูลไม่ครบส่งได้เมื่อเลือก“ส่งเท่าที่ทำได้”พร้อมmissing fields ไม่เติม0; ครั้งแก้ไขใหม่เชื่อมpreviousAttemptId

| ความช่วย | “ใช้คำใบ้หลักการ1ครั้งและเครื่องคิดเลข” | ดูรายการตามจริง |
| ฝึกต่อ | “ลองตรวจว่ากล่อง13ให้ปริมาณพอหรือไม่” | ฝึกเรื่องกล่อง/งานใหม่/ผูกกับพอร์ต |

ไม่มีreviewerจริงในต้นแบบ ไม่มีปุ่มให้ผู้เล่นแก้statusเป็นconfirmed ครูreviewเป็นงานต่อยอดตามสิทธิ์และauditที่ยังต้องกำหนด

## 7. PORTFOLIO — พอร์ต

หน้าแรกcardผลงานและfilterวิชา/ทักษะ/วันที่ มีชื่อ ภาพ เป้าหมาย และป้ายแยกโลก/หลักฐาน/ช่วย ไม่จัดอันดับจากงบเหลือหรือความสวย
หน้าผลงานมี5ส่วน: เป้าหมายและเงื่อนไข; แผนแรก/แผนใช้จริง; การแก้และผลโลก; assessment/evidence; reflection ผู้เล่นfeatured/reorder/editชื่อ/ปก/reflectionได้ ระบบrecordsอ่านอย่างเดียว

| รายการที่ดู | สิ่งที่เก็บและแสดง |
| --- | --- |
| แผน | revisionIdsแรก/ใช้จริง/สำคัญพร้อมวันที่ เปรียบเทียบค่าที่แก้ |
| โลก | material,cost,actual/reserve,reachability,summary,image ตอนsnapshot; live stateแสดงแยก |
| ความรู้ | task/version/objective,field checks,reasoning pending,help/tools,priorExposure |
| พัฒนาการ | งานแรก/ล่าสุดตามเงื่อนไข ไม่อ้างคะแนนเทียบกันเมื่อโจทย์และช่วยต่าง |
| Reflection | “อะไรทำให้เปลี่ยนแผน?” “ตรวจว่าพออย่างไร?” “ครั้งหน้าจะตรวจอะไร?” |

“บันทึกโครงการสำเร็จ”ต้องผ่านพื้นที่/สำรอง/งบ/ทางเข้าถึง/ภาพ/สรุปตามกติกา; ถ้ายังไม่ครบมี“เก็บงานระหว่างทำ”แยกdraft work ไม่ให้รางวัลสำเร็จ การประเมินยังpendingไม่ห้ามเก็บโครงการที่โลกสำเร็จ
แก้ห้องหลังsnapshotเปิด“สร้างฉบับใหม่”คงฉบับเดิม คืนวัสดุจนliveสำรองขาดขึ้น“โครงการปัจจุบันต้องปรับ”ภาพเก่ายังคงผลตอนบันทึก ไม่เปลี่ยนsnapshotเงียบ ๆ
ภาพต้องreferenceblobที่ตรวจแล้ว; ถ่ายภาพเฉพาะพื้นที่โครงการไม่จับหน้าassessment/ข้อมูลส่วนบุคคลอัตโนมัติ ถ้าจับภาพล้มเหลวเก็บdraftและลองใหม่ ไม่อ้างsuccessครบภาพ

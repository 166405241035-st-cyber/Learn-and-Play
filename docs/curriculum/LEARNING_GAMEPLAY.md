# การเรียนผูกกับเวลาเล่นและความยากอย่างไร

ฉบับออกแบบ0.1 — 9ตุลาคม2026; ยังไม่implemented
อ่าน [หลักสูตร](CURRICULUM_MAP.md), [ชุดแรก](FIRST_LEARNING_UNIT.md), [ความยาก](../game-design/DIFFICULTY.md)

## 1. สองวิธีเริ่มที่ใช้ข้อมูลเดียวกัน

เริ่มจากโครงการ: เลือกเป้าหมาย→อ่านเงื่อนไข→ร่างแผน→พบเรื่องที่ติด→เปิดบทตรงจุด→กลับแผน→ทดลองและแก้→สรุป/ประเมิน/พอร์ต
เริ่มจากความรู้: เลือกทักษะ→เรียน/ฝึก→เห็นโครงการที่ใช้ทักษะนั้น→เลือกโครงการ→ใช้และตรวจ→ประเมิน/พอร์ต
ไม่ต้องผ่านทุกบทก่อนเดินหรือแต่งห้อง ผู้รู้แล้วส่งงานแสดงความรู้ได้โดยข้ามการฝึกซ้ำ pendingไม่ปิดความช่วยหรือโครงการทดลอง

## 2. จุดเชื่อมในเกม

| เหตุการณ์ | ระบบเรียนทำอะไร | สิ่งที่เก็บเป็นหลักฐาน |
| --- | --- | --- |
| อ่านป้าย/แปลน | หน่วยและข้อมูลเปิดซ้ำได้ มีปุ่มบทที่เกี่ยวข้อง | task/version; อ่านเงื่อนไขไม่ใช่hint |
| ร่างพื้นที่ผิด | ชวนดูช่องหน่วย/แยกพื้นที่กับด้าน ไม่แก้คำตอบเอง | first/latest draft; misconceptionถ้ามีหลักฐานพอ |
| หารกล่องเป็นทศนิยม | ทดลองจำนวนเต็มต่ำ/สูงและคูณกลับ | principle/calculation/check; helpUsed |
| เทียบตะกร้า | แสดงค่าใช้จ่ายและงบจากจำนวนที่ผู้เล่นเลือก | แผนใช้จริง; ยังไม่มีผลassessment |
| ปู/คืน/ถอน | แสดงปริมาณซื้อ ปู เหลือ และเหตุผลโลกไม่ผ่าน | transaction/resource state; ไม่ยืนยันmastery |
| สรุปผลงาน | ให้เลือกแผนสำคัญ ภาพ และreflection | portfolio snapshot; ผลโลกแยกจากassessed evidence |
| ส่งงานใหม่ | ตรวจค่าที่นิยามได้ เก็บเหตุผลรอตรวจ | task snapshot คำตอบช่วยเครื่องมือและผลรายด้าน |
| กลับมาภายหลัง | เลือกฝึกหรือทำงานใหม่ตามทักษะที่สนใจ | ระยะห่างและrevision ถ้ามีงานretentionที่พร้อมจริง |

ต้องตั้งชื่อsubject/skillในแต่ละกิจกรรม ไม่อ้างว่ากดวัตถุแล้วเรียนรู้โดยอัตโนมัติ บทเรียนสำคัญต้องมีคำอธิบายตรง ๆ และตัวอย่างให้ตรวจได้

## 3. เวลาเล่นที่เสนอเพื่อทดสอบ

เวลาเหล่านี้เป็นประมาณการ UX ไม่ใช่เวลาเรียนมาตรฐานหรือเกณฑ์ความเก่ง ไม่มีการนับถอยหลังในกิจกรรมทั่วไป

| ช่วง | ช่วงเวลาทดลองเสนอ | พฤติกรรม |
| --- | --- | --- |
| เลือกเป้าหมาย/อ่านข้อมูล | 3–5นาที | เดินหรือเปิดข้อมูลจากแผนได้ |
| บททบทวนหนึ่งเรื่อง | 2–4นาที/บท | อ่าน→ลองหนึ่งขั้น→กลับแผน พักและย้อนอ่านได้ |
| วางแผน/เทียบวัสดุ | 5–10นาที | ผู้รู้แล้วข้ามตัวอย่างได้ |
| ซื้อและจัดพื้นที่ | 5–10นาที | แก้และทดลองตามกติกา |
| ประเมินข้อมูลใหม่ | 5–10นาที | ไม่จับเวลา บันทึกร่างและขอช่วยได้ |
| สรุปพอร์ต | 3–5นาที | บันทึกก่อนหรือหลังประเมินได้ |

หากเรียนครบ8บท แผนตัวอย่างรวม37–72นาทีโดยประมาณ จึงควรแบ่งเล่นหลายครั้ง ไม่บังคับจบในครั้งเดียว ผู้ไม่ต้องทบทวนมีเวลาแตกต่าง ไม่มีโบนัสความรู้จากทำเร็ว
ปิดหน้าจอเรียนกลับโลกได้โดยร่างไม่หาย เปิดเมนู/บทเรียน/ประเมินพักเวลาโลกและทรัพยากร เวลาmotionตกแต่งไม่กระทบคะแนน เวลาexamแยกจากtimeโลกเมื่อทำภายหลัง
การบันทึกร่างคือข้อกำหนดที่จะพัฒนา ยังไม่มีsaveในrepository จนimplementedห้ามสื่อว่าเล่นแล้วปิดได้ปลอดภัย

## 4. ความยากสามแกนในชุดแรก

| รูปแบบ | ความช่วยที่เสนอ | ความซับซ้อน | ความเปิดกว้าง / หลักฐาน |
| --- | --- | --- | --- |
| GUIDED | สูตร ตัวอย่าง ตรวจทีละขั้น; เก็บที่ใช้จริง | 4×6 เผื่อ10% A/B | เลือกเป้าหมาย วัสดุและจัดของ; เป็นpracticeถ้าใช้วิธีเต็ม |
| INDEPENDENT | ไม่แสดงเฉลยก่อนส่ง แต่เรียกช่วยได้ | 3×5 C/D ข้อมูลใหม่ | เลือกวิธีและอธิบาย; บริบทเดิมไม่ใช่broad transfer |
| COMPAREระยะต่อไป | เรียนฐานส่วนลด/ค่าส่งก่อน | หลายขั้นมีค่าส่งและส่วนลด | เปรียบเทียบแผนตามกติกาปัดราคา; planned |
| SHAPEระยะต่อไป | เครื่องมือแบ่งรูปและคำใบ้ | รูปเว้าที่กำหนดแน่นอน | เลือกวิธีแบ่งและตรวจ; planned |
| OPENระยะต่อไป | เข้าบททบทวนได้ตลอด | ขนาด/งบ/วัสดุในชุดที่ตรวจว่ามีทางออก | ตั้งเป้าหมาย ทดสอบสองแผนและเมื่อเงื่อนไขเปลี่ยน; planned |

แนะนำระดับรายobjectiveจากหลักฐานพร้อมเงื่อนไข ไม่จัดเก่ง/อ่อนจากเงิน เวลา หรือความสวย เปลี่ยนข้อมูลสร้างattemptใหม่เก็บร่างเดิม ไม่เปลี่ยนข้อจำกัดกลางโครงการ การลดmotion/ขยายตัวหนังสือไม่ใช่helpในการทำคณิตศาสตร์

## 5. ทำให้การตัดสินใจมีความหมาย

ทางเลือกต้องมีผลที่ตรวจได้: Aเหลืองบมากกว่า Bมีปริมาณสำรองมากกว่า โดยไม่สมมติความทนทาน; ผู้เล่นเลือกความสำคัญเอง งานอื่นอาจเลือกกราฟ/แบบจำลอง/วิธีสร้างแทนวัสดุ
ข้อผิดต้องกู้ได้: แสดงขั้นที่ติด ชวนตรวจหรือฝึกย่อย ไม่สุ่มทำวัสดุหายเพื่อสอน ไม่ลดคะแนนเพราะทดลองแก้ ไม่ล็อกเรียนหลังใช้เงินหมด
การจัดห้องทำให้เห็นผลงานตามเป้าหมาย ส่วนการอธิบายและงานใหม่ให้หลักฐานความรู้ ต้องมีทั้งสองส่วนเพื่อไม่ให้เกมกลายเป็นเพียงกดซื้อหลังกรอกคำตอบ

## 6. งานถัดไปก่อนกลับไปหน้าจอ

1. ตรวจรหัสตัวชี้วัด/ผลการเรียนรู้และความลึกของ8objectiveจากแหล่งฉบับเต็ม รวมพื้นฐานประถมที่ใช้ทบทวน
2. ครูตรวจบทสอน ข้อผิด ตัวอย่างหลักฐาน และความเหมาะสมเครื่องมือ; เกณฑ์mastery/retentionยังpending
3. ออกแบบช่องร่างแผน/งานประเมินและfeedbackตาม8objective ไม่ใช้แบบฟอร์มคำตอบสุดท้ายช่องเดียว
4. ปรับTaskDefinition/Objectiveให้เชื่อมlesson/practice/assessment/portfolioด้วยIDและversionก่อนimplementation
5. สร้างprototypeเฉพาะชุดแรกเมื่อสั่งเริ่มโค้ด แล้วทดสอบจุดที่ผู้เล่นติด/พัก/กลับมาทำต่อ แทนเพิ่มหลักสูตรทุกบทพร้อมกัน

เกณฑ์ตรวจรับการเชื่อม: ผู้เล่นบอกได้ว่าต้องหาอะไร มีบทตรงเรื่องที่ติด กลับแผนโดยร่างไม่หาย แก้ความผิดได้ รับผลที่แยกpending และพอร์ตแสดงทั้งผลโครงการกับเงื่อนไขการเรียน ไม่ใช้ความยากหรือชื่อวิชาเพื่อสร้างmasteryเอง

## 2. ผลตรวจคณิตศาสตร์และตัวอย่างข้อมูล

ตรวจด้วยจำนวนเต็ม cm² และอัตรา basis points ใน scratch; ไม่ใช่ runtime test หรือการรับรองหลักสูตร

| งาน | พื้นที่จริง / ต้องเตรียม (ตร.ม.) | แผนและค่าใช้จ่าย | ผล |
| --- | --- | --- | --- |
| GUIDED | 24 / 26.4 | A18=3,240; B14=3,500 | ทั้งคู่ผ่านงบ4,000; สำรอง3/4 |
| INDEPENDENT | 15 / 16.5 | C14=1,960; D11=1,980 | ทั้งคู่ผ่านงบ2,100; สำรอง1.8/1.5 |
| COMPARE | 24 / 26.4 | Aรวมส่ง3,440; Bลดค่าสินค้าเหลือ3,325 | ทั้งคู่ผ่านงบ3,500; Bถูกกว่า115 |
| SHAPE | 20 / 22 | A15=2,700; B11=2,750 | ปริมาณ22.5/22; ตำแหน่งส่วนเว้ายังต้องกำหนด |

SAVE_EXAMPLE: A18 เปิด16 ปู240,000cm² กล่องปิด2รวม30,000cm²; ปริมาณสุทธิ270,000สมดุล; เงินเหลือ760ถูกต้อง การอ้างอิง project/attempt/plan/assessment ตรงกัน ไม่มี mastery unlock และหลักฐานยัง pending

## 3. ช่องว่างที่ต้องแก้ก่อนใช้ข้อมูลจริง

1. Envelope ใน SAVE_DESIGN ต้องระบุ `plans` และ `evidence` ให้ตรงกับ JSON ตัวอย่างด้วย ส่วนภาพต้องออกแบบ manifest/blob package ก่อน import ที่ตรวจครบได้
2. TaskDefinition ต้องระบุ `responseKind` และ `graderKind` ใน snapshot เพื่อส่งงานถูกตัวตรวจเมื่อเพิ่มวิชาและโหลดเนื้อหารุ่นเก่า อย่าพึ่ง subject ปัจจุบันแทน snapshot
3. `DimensionResult.evidenceRefs` ใน fixture อ้างถึง assessment ต้นทาง ไม่ใช่ Evidence.id; ต้องกำหนดความหมายให้ชัดเพื่อไม่ให้ validator ปฏิเสธตัวอย่างหรือวนอ้างอิง
4. ภาพ `synthetic-cover-1`, layout ว่าง และค่าทางเดิน/ผลโลกใน fixture เป็นตัวอย่างประกอบเท่านั้น ไม่ใช่หลักฐานภาพหรือผล pathfinding ที่ตรวจจริง ห้ามรับ JSON นี้เป็น runtime save โดยตรง
5. ผล `numeric-fields-correct` ยืนยันเฉพาะช่องตัวเลขที่ส่ง ไม่ยืนยันว่าผู้เรียนอธิบายวิธีตรวจได้ครบด้าน calculate-check ต้องแสดงขอบเขตผลนี้ใน UI
6. COMPARE ยังต้องกำหนดปัดราคาสำหรับข้อมูลอื่น; SHAPE ต้องมีเซลล์ที่ตัดแน่นอน; OPEN ต้องกำหนดงบและชุดวัสดุที่มีทางออกก่อนพร้อมเล่น

## 4. งานเขียนเกมที่เตรียมไว้ — ยังไม่เริ่ม

AGENTS จำกัดงานปัจจุบันไว้ที่เอกสาร/setup การเริ่ม scaffold เป็นขั้นถัดไปเมื่อผู้ใช้สั่งเริ่มเขียนเกมโดยตรง ไม่ต้องรอภาพจริงเพื่อทำต้นแบบ placeholder และไม่ต้องเลือก hosting ก่อนทดสอบในเครื่อง

| ลำดับ | งานที่เสนอ | เกณฑ์ตรวจรับ |
| --- | --- | --- |
| 1 | เตรียม Vite/TypeScript/Phaser แยก template แล้วรวมโดยรักษา docs | pin เวอร์ชันที่เข้ากับ Node22.19.0, lockfile, typecheck/build; ยังไม่มี deploy |
| 2 | หน่วย/สูตรและกติกาซื้อเปิดคืนปูถอนเป็นโมดูลแยกโลก | A/Bผ่าน; A17ไม่พอ; คืนเกิน/ซื้อเกินงบไม่ได้; คำสั่งซ้ำไม่หักซ้ำ |
| 3 | ฉาก placeholder + เดิน + แผน/บทเรียน + ร้าน + จัดพื้นที่ | เลือกเป้าหมายและแก้ได้; มุมบนใช้หน่วยจริง; ทางเดินถึงจุดสำคัญ; คำใบ้เข้าถึงได้ |
| 4 | C/D assessment + result + portfolio snapshot | บันทึก help/tools; ตัวเลขกับเหตุผลแยก; pending ไม่สร้าง mastery; แก้ caption ไม่แก้ผล |
| 5 | IndexedDB + export/import และ mock วิชาอื่น | reloadสมดุล; importเสียไม่ทับข้อมูล; ไม่ replayรางวัล; mockส่งตัวตรวจถูกวิชา |
| 6 | ตรวจภาพ sample แล้วผสานภาพที่อนุมัติ | canvas/anchor/ทิศ/แสงตรงกัน; เดินสองเฟรมไม่เปลี่ยนรูป; มีข้อมูลแหล่งและสิทธิ์ |

ก่อนเพิ่มรูปทรง/โครงการเปิด/จับเวลา ให้ทำ slice GUIDED→INDEPENDENT→พอร์ต→save/reload ให้ตรวจได้ก่อน เกณฑ์ mastery และการตรวจครูเป็นงานค้างแยกจากการสร้างเกมให้เล่นได้

## 5. ตรวจ sample ภายนอกต่อ

ใช้ [STYLE_SAMPLE](../../asset-prompts/style/STYLE_SAMPLE.md) เริ่ม idleหนึ่งภาพ เดินSEสองเฟรม พื้นหญ้า และโต๊ะ ตรวจคู่เดินก่อนขยายทิศ/NPC/อาคาร สถานะ ready หมายถึงพร็อมป์พร้อมเท่านั้น

ตรวจขนาดจริง RGBA เท้า(80,176) รูปเพชร128×64 ฐานโต๊ะ(128,224) footprint2×1 แสงบนซ้าย และความชัดเมื่อย่อ; เงาที่แยกต้องมีไฟล์/anchor ชัด หรือใช้เงา placeholder จากโค้ดในต้นแบบ ห้ามใส่ตัวเลข สูตร ราคา หรือข้อความไทยลง bitmap

ขณะนี้ยังไม่มีภาพให้ตรวจ จึงคงสไตล์และขนาดเป็นข้อเสนอ ไม่เปลี่ยน registry เป็น approved/integrated
